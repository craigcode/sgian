# Sgian — Deep Review Findings (2026-07-01)

Seven parallel review agents covered the transport/security layer, daemon core state,
daemon runtime/persistence, control CLI, frontend, and CI/build/distribution, plus a
verification run of all test suites. Every finding below was verified against the actual
code and cross-checked against the test module so already-pinned behavior is not
re-reported as a defect.

**Repo health at review time:** `cargo test` 315 passed, vitest 238 passed,
clippy/fmt clean, `cargo audit` clean (19 informational unmaintained-GTK3 advisories,
Linux-only transitive deps of Tauri).

---

## Critical / High

### H1. GUI settings save always fails — `ui/src/main.js:1447`
The settings modal invokes `"write-config"`, but the backend registers the command as
`write_config` (`src-tauri/src/lib.rs:3648`). Every save from the GUI fails with
"command not found"; only `ctl write-config` works. Nothing tests the invoke boundary —
settings tests cover only pure serialize/validate functions and `main.js` has zero tests.
The browser-preview `invoke()` fallback (`main.js:339–402`) also lacks a `write-config`
branch.

### H2. Daemon-wide wedge via blocking PTY write under the store mutex — `lib.rs:2359–2376`
Found independently by two reviewers. `write_to_pane` calls `writer.write_all` on the PTY
master while holding the `TerminalStore` mutex. If a pane's foreground process stops
reading stdin (Ctrl-S flow control, stopped job, wedged program) and a client sends a
large paste, the write blocks on the full kernel PTY buffer — and every request needing
that lock (bootstrap, list, snapshot, find, `wait`'s 20 ms tick, persist, config reload)
hangs. `Broadcast` (`lib.rs:2919`, `write_to_all_live` at 2392) lets one wedged pane
freeze input to all panes. This is the one violation of the codebase's otherwise-strict
"no lock across blocking I/O" discipline.

### H3. No client-side read timeout — `lib.rs:4721–4744`
`DaemonConnection::read_response` waits forever. When H2 fires, every synchronous Tauri
command hangs and the GUI's invoke promises never resolve. Only `bootstrap_workspace`
gets a frontend timeout (`main.js:540`).

### H4. Resize OOM — `lib.rs:2890, 2402, 2037`
Resize dimensions are clamped only from below (`cols.max(2), rows.max(1)`).
`resize_pane_terminal(pane, 65535, 65535)` — a u16 straight from JS — makes the vt100
model allocate a ~4.3-billion-cell grid, OOM-killing the daemon and every shell it owns.
The same applies via tampered persisted `sizes` at spawn (`lib.rs:2121–2128, 2199`).
No test pins an upper clamp.

### H5. Windows transport is broken at runtime — `lib.rs:634, 661, 674–698, 5007`
The stated bar is "compiles on Windows," but the runtime defects are concrete:

- The overlapped accept treats `raw_os_error() == 535` as `ERROR_IO_PENDING` and `534`
  as `ERROR_IO_INCOMPLETE`; the real values are **997 / 996** (535 is actually
  `ERROR_PIPE_CONNECTED`, 534 is `ERROR_ARITHMETIC_OVERFLOW`). A normal pending connect
  is treated as a fatal listener error; `WouldBlock` mapping never triggers. The accept
  loop cannot work.
- On the recreate-failure fallback (`lib.rs:674–698`), the same pipe HANDLE ends up owned
  by both the listener (`self.handle`) and the returned stream — a double `CloseHandle`
  (use-after-free class; can close an unrelated reused handle).
- `create_token` (`lib.rs:5007–5013`) reads `/dev/urandom` unconditionally, so no daemon
  token can ever be created on Windows.

The SID-scoping and fail-closed null-descriptor design are sound.

### H6. Release pipeline discipline — `.github/workflows/ci.yml`
- The `release` job has no `needs: [check, build]` — on a `v*` tag all jobs run in
  parallel and signed, notarized artifacts can be published before the test job fails.
- `Swatinem/rust-cache` runs inside the signing job (`ci.yml:68–70`): cache-restored
  object files from any main-branch run get linked into the Developer-ID-signed binary
  (cache-poisoning laundering path). Release builds should compile from scratch.
- All actions are pinned to mutable tags (`@v4`, `@v2`, `@stable`) rather than commit
  SHAs — the tj-actions/changed-files attack pattern, and `action-gh-release` runs with
  `contents: write`.

### H7. fish quoting breaks `ctl run`'s contract, and `run` can hang forever
- `shell_quote` (`lib.rs:6371–6387`) is POSIX-only but args are quoted before the shell
  family is known (`parse_run_args`, 6449–6453). In fish, `\\` and `\'` are escapes
  inside single quotes: backslash-bearing args are silently corrupted, and an arg ending
  in `\` (e.g. `C:\tmp\`) unbalances the wrapper so the exit marker never prints.
  Contradicts the README's "POSIX shells and fish both see correct status."
- `run_in_pane` (`lib.rs:6545–6575`) has no timeout and `ctl run` exposes no `--timeout`
  (the doc comment at 6497 says "the caller may wrap this in a timeout"; `control_run`
  at 6899–6925 never does). Any marker miss — the quoting bug above, a foreground
  `vim`/REPL in the pane, or a shell outside sh/bash/zsh/fish (everything non-fish is
  assumed POSIX by `detect_shell_family`, 6338–6348) — is an infinite hang.

## Medium — config layer quietly undoes operator intent

- **M1. `write_config` erases `scrub_env`** (`lib.rs:1053–1064` vs `2953–2972`):
  `full_config()` omits `scrub_env`, but the `WriteConfig` handler deserializes the full
  `Config` struct (missing field → serde default `[]`) and persists it atomically over
  workspace config.json. Any get→write round-trip silently drops the scrub list; newly
  spawned panes inherit the secrets again. No test covers `scrub_env` surviving a
  round-trip. (Masked for the GUI path by H1; `ctl write-config` hits it.)
- **M2. Malformed config silently becomes defaults** (`read_config_file`,
  `lib.rs:1103–1108`): one syntax error in config.json silently discards `scrub_env`,
  custom shell, and idle settings with no log; the file-watch reload (`reload_config`,
  3316) even broadcasts the defaulted config as a legitimate `ConfigChanged`.
  Workspace.json corruption is surfaced (`workspace_was_corrupt`, 2653); config isn't.
- **M3. `0` can't override** (`Config::overlay`, `lib.rs:1000–1004`): workspace
  `idle_shutdown_secs: 0` cannot cancel a non-zero global value (0 ≡ unset), so the
  daemon kills that workspace's shells after the global idle window. Same pattern for
  `shell_args` (990–994). A test pins this shape — knowingly-shaped but user-hostile;
  fields want to be `Option`.
- **M4. `idle_shutdown_secs` doesn't hot-reload** (`lib.rs:4118`): read once before the
  accept loop; `status --verbose` reports the new value while the old one is enforced.

## Medium — other daemon and CLI issues

- **M5. Zombie leak on close/restart** (`lib.rs:2235–2237`): a superseded PTY reader
  `return`s before `child.wait()`; portable-pty's unix child does not reap on Drop, so
  the SIGHUP'd child stays a zombie for the daemon's lifetime. Generation safety of
  *emission* is tested; reaping of superseded children is not.
- **M6. Unbounded OSC title** (`TitleSink`, `lib.rs:1592–1596`): vte's `osc_raw` is an
  unbounded `Vec<u8>`; a pane emitting `\x1b]2;` plus endless non-terminator bytes grows
  daemon memory at PTY drain speed; a multi-megabyte title is then cloned on every
  snapshot/find. The 256-char `MAX_TITLE_CHARS` cap applies only to rename titles.
- **M7. Idle shutdown ignores non-subscriber clients** (`lib.rs:4168–4181`): a blocked
  `ctl wait` (framed connection, not a subscriber) or a quiet persistent v2 connection
  doesn't count as liveness — an idle-configured daemon can exit mid-wait, killing
  shells. Mitigated by the default `idle_shutdown_secs = 0`.
- **M8. Subscribe-then-send race** (`lib.rs:6521–6540`; same pattern in attach at
  5989–5994): `Subscribe` is written on one connection, `SendInput` on another, with no
  ack — the daemon can broadcast the marker before registering the subscriber. With H7's
  missing timeout, a lost marker is a forever-hang.
- **M9. `ctl attach` duplicates output** produced between subscribe and the
  `GetScrollback` read (`lib.rs:5989–6003`) — printed once from the scrollback dump,
  again from the event stream.
- **M10. `ctl logs --follow` stalls after rotation** (`lib.rs:7132–7160`): it follows
  the original inode; `BoundedFileWriter` renames to `daemon.log.old` and creates a
  fresh file, so the follower reads 0 bytes forever with no error.
- **M11. Frontend bootstrap clobbers events** (`main.js:499–506`): `bootstrap()`
  wholesale-replaces `state.panes`/`state.paneStates` after backend events are wired; a
  `ctl new` landing between snapshot computation and response processing is added by
  `handlePaneCreated`, then erased — permanently invisible in the GUI.
- **M12. No daemon-restart/reconnect story** (`main.js`): events subscribe once,
  `bootstrap()` runs once, nothing detects a dead daemon — stale panes plus a
  `[sgian] failed to write…` error line per keystroke. Layout/active-pane/resize write
  failures are `console.warn`-only (silent layout loss on next launch).
- **M13. Malformed persisted layout corrupts further** (`main.js:504–506, 913, 954,
  1067` + `layout.js:101–107`): `layoutMatchesPanes` validates only leaf ids; a split
  node with a missing ratio yields `NaN` (`Math.max(0.18, NaN) === NaN`) which
  `JSON.stringify` writes back as `null`; a structurally bad node makes
  `renderNode(undefined)` throw during boot → full boot-error screen despite healthy
  panes.
- **M14. Startup pane view leak** (`main.js:438–455` vs `499–531`): `showStartupPane`
  creates a real xterm view for hardcoded `pane-1`; `bootstrap()` replaces state without
  disposing views absent from the snapshot — xterm instance + ResizeObserver + buffer
  leak for the app's lifetime in any workspace not containing `pane-1`.
- **M15. `disable-library-validation` is unjustified** (`entitlements.plist:8–10`): the
  in-file rationale ("spawned tools") is incorrect — library validation only governs
  dylibs loaded into the app's own process; child PTYs are unaffected. It needlessly
  re-enables dylib injection. `allow-jit` is the only entitlement WKWebView needs.
  README drift: still lists `allow-unsigned-executable-memory`, removed in c8372f9.
- **M16. CI coverage gap** (`ci.yml` vs `README.md:159–164`): CI never runs the 238
  vitest tests nor the documented `cargo check --target x86_64-pc-windows-gnu`; and the
  build job hard-requires `secrets.TAURI_SIGNING_PRIVATE_KEY` on `pull_request`, so
  fork PRs always fail with an opaque error.
- **M17. `legacy_workspace_key` uses `DefaultHasher`** (`lib.rs:5277–5281`), documented
  as unstable across Rust releases — a toolchain bump can silently miss the old data dir
  and reseed a fresh workspace, stranding panes/scrollback. No one-time migration to the
  FNV key is performed.
- **M18. Stub-feed script uses predictable `/tmp` path**
  (`tools/updater-stub/setup-stub-feed.sh:40, 179–193`): fixed world-writable
  `/tmp/sgian-feed`; `mkdir -p` accepts a pre-existing attacker-owned dir or symlink,
  then `cp -f`/`cat >` write through it (multi-user symlink clobber).

## Low (notable)

- **L1.** Exit markers are predictable/forgeable by pane-resident code
  (`lib.rs:6529–6535`): `__sgian_rc_{pid}_{static}_{pane_id}`, no random component;
  the comment at 6355 claims "pid + timestamp" — comment/code mismatch either way.
- **L2.** `ctl run` exit codes are reported in output but the CLI always exits 1 on
  failure (`lib.rs:6920–6924, 7305–7307`) — scripts must parse stdout/JSON.
- **L3.** Global `--json`/`--help` intercepted anywhere in non-freeform commands
  (`lib.rs:5661–5670`): `ctl new --name --json` fails; `ctl new --name -h` prints help.
  The `--` escape exists but is undocumented.
- **L4.** Unknown flags after the first positional are silently accepted as positionals
  (`lib.rs:5675–5677`): `ctl panes --jsonn` silently prints the human list.
- **L5.** `ctl pane <cmd>` is not a true alias (`lib.rs:5741–5760`): it strips
  `--json`/`--workspace` from what becomes the freeform payload, diverging from the
  direct command (pinned at 8262 for the direct form).
- **L6.** `send`/`broadcast` can't transmit literal `--lf`/`--raw` tokens and lack
  `--help` handling (`lib.rs:7270–7280, 5943`).
- **L7.** `ctl new --name a b` silently creates pane `b`; `ctl new a --name b` errors —
  order-dependent, lossy (`lib.rs:7173–7196`).
- **L8.** `wait --text/--regex` samples the visible screen at 20 ms (`lib.rs:3048–3113`):
  fast-scrolling matches are missed; soft-wrapped needles never match (rows joined with
  `\n`). Timeout-less waits from disconnected clients poll forever.
- **L9.** Scrollback cap can cut mid-ANSI-escape (`lib.rs:5230–5243`) — UTF-8 boundaries
  are fixed, CSI/OSC boundaries aren't; replay can start inside a broken sequence. Each
  cap event also re-reads the full ≥16 MB file on the append hot path.
- **L10.** `PaneModel::reset` wipes content without bumping the revision
  (`lib.rs:1632–1635`): revision N maps to two different screens across a restart;
  revision-deduping clients miss the wipe.
- **L11.** `clean_title` doesn't strip control chars/ANSI escapes (`lib.rs:5352–5362`):
  a rename title with `\x1b[2J\n…` is stored verbatim, log-injected via tracing
  (`title = %pane.title`, 2855) and escape-injected into terminals printing pane lists.
- **L12.** Slow subscriber at the 1024-slot queue limit is disconnected entirely, not
  skipped (`lib.rs:1976–2000`) — a fast `cat` of a large file can kick a live
  GUI/`ctl attach` mid-stream. Intentional design; the disconnect-on-burst behavior
  itself is untested.
- **L13.** `OutputRouter.closed` grows monotonically (`lib.rs:1863–1867`); pane ids are
  never pruned (tiny, unbounded in principle).
- **L14.** `next_pane_id_after` overflows on a tampered `pane-18446744073709551615`
  (`lib.rs:5342–5350`); duplicate persisted pane ids aren't deduplicated.
  `reaped_exit_code` (1571–1580) keys off portable-pty's `Display` string — pinned
  today, brittle across a dependency upgrade.
- **L15.** `BoundedFileWriter` exceeds the cap on a single oversized write and reports
  `Ok(len)` while dropping data on failed reopen (`lib.rs:3855–3872`; documented
  best-effort).
- **L16.** Sub-second dirty-state loss window on graceful shutdown (`lib.rs:4207–4209`):
  a `mark_dirty` after the final `take_dirty` is lost; the final flush isn't ordered
  after in-flight handlers.
- **L17.** Lingering connection threads hold `Arc<DaemonServer>` clones, so
  `TerminalSession::drop` may never run at shutdown (`lib.rs:4211–4213`); SIGHUP-ignoring
  children can leak past daemon exit.
- **L18.** Handshake timeout is per-read, not per-connection, and there is no
  concurrent-connection cap (`lib.rs:4245, 4428, 4147`): a same-UID slowloris pins
  threads/buffers. Low severity — the socket is owner-only.
- **L19.** GUI subscription reconnect can busy-loop when connect+auth succeeds but the
  stream EOFs immediately (`lib.rs:2611–2628`; backoff only on connect/write failure).
- **L20.** `handle_wait` spins forever on a poisoned per-pane model lock without
  `--timeout` (`lib.rs:3063–3065`).
- **L21.** `resolve_workspace_dir` silently retargets the parent when cwd is literally
  named `src-tauri` (`lib.rs:5385–5387`) — dev heuristic leaking into production.
- **L22.** `events.js:42–49`: `handlePtyOutput` marks state live before existence check,
  re-inserting `paneStates` entries for deleted panes (slow growth under churn).
- **L23.** Only `bootstrap_workspace` gets `withTimeout` (`main.js:540–553, 1099–1105`):
  a hung `create_pane` leaves `pendingLocalCreates > 0` forever, so the 120 ms reconcile
  timer re-schedules eternally and `ctl`-created panes never place.
- **L24.** macOS Ctrl+Shift chords are indistinguishable from Cmd chords
  (`keyboard.js:42–99`, `mod = ctrlKey || metaKey`) and are swallowed instead of
  reaching the PTY; `|`/`_` split chords unreachable on some layouts. Pinned/deliberate
  tradeoff.
- **L25.** CI keychain teardown doesn't restore the original default keychain/search
  list and leaves `certificate.p12` in `$RUNNER_TEMP` (`ci.yml:88, 105–106, 135–138`) —
  matters on shared/self-hosted runners.
- **L26.** `action-gh-release` lacks `fail_on_unmatched_files: true` (`ci.yml:140–146`):
  a bundler layout change ships a release silently missing the DMG or updater
  tarball/sig. No checksums published.
- **L27.** `updates.sgian.dev` may be unprovisioned ("real hosting is deferred") — a
  lapsed/squatted domain can't serve malicious payloads (signature check) but can freeze
  or break updates.
- **L28.** Stub-overlay builds and production builds write the identical artifact path —
  a manual release from a dev machine could ship a stub-configured (localhost, insecure
  transport) app. CI is immune (fresh checkout).
- **L29.** Stub-feed script: unescaped `$FEED_VERSION`/`$SIGNATURE` in the JSON heredoc;
  "port 8787 in use ⇒ assume feed served" exits 0 against any unrelated process.
- **L30.** Doc drift: README claims 215 Rust tests (actual: 315); read-only command list
  omits `logs`/`wait`/`snapshot`/`find`; says `shutdown` "requires a running daemon"
  while the code deliberately succeeds with "no daemon running".

## Verified sound (non-findings)

- **Wire/auth:** frame length validated before allocation, u32→u64 widening, clean
  truncated-header vs EOF distinction; auth-before-dispatch; version negotiation is pure
  `min` with no downgrade-bypasses-auth path; constant-time token compare; `create_new`
  (O_EXCL) token creation races correctly; `remove_stale_socket` refuses symlinks;
  flock-serialized single-daemon startup incl. the shutdown/respawn race.
- **State:** `drain_complete_utf8` correct (split multibyte tails, U+FFFD, EOF flush);
  generation-safe exactly-once `PaneEnded`; consistent registry → terminals → layout
  lock ordering (H2 is the only blocking-I/O-under-lock violation); subscriber catch-up
  stress-tested; per-pane model locks never held across sleeps.
- **Persistence:** correct temp→fsync→rename→dir-fsync with 0600; pane-id validation
  blocks path traversal (re-validated in `prune_orphan_scrollback`); workspace-key
  collisions refused on both sides; layout/title/frame caps enforced and pinned.
- **Frontend security:** zero `innerHTML`/`insertAdjacentHTML` in ui/src; all untrusted
  strings via `textContent`/`createElement`/`value`/xterm; OSC titles never become DOM;
  theme colors via CSSOM.
- **Distribution:** insecure updater stub quarantined in an explicit `--config` overlay
  that cannot reach the CI release path; minisign pubkey + https endpoint committed;
  capability surface exactly matches the 12 commands, `main` window only; strict CSP;
  lockfiles committed, `npm ci` used; CI secrets consumed via `env:` without log
  exposure.

## Structural observation

Test coverage is high in volume but inverted in placement: the pure modules (layout,
keyboard, zoom, parsers, frame codec) are near-exhaustively pinned, while the
orchestrators — `main.js` (0 tests) and the cross-process choreography (subscribe acks,
non-draining PTYs, daemon restart) — are where every high-severity finding lives.

## Recommended fix order

1. **H1** — rename the invoke to `write_config`; add one happy-dom integration test that
   boots main.js against a stubbed `__TAURI__` to pin command names and boot ordering.
2. **H2/H3/H4** — upper-clamp resize dims; move the PTY write out from under the
   terminals mutex (per-pane writer or write timeout); add a client read timeout.
3. **H6** — `needs: [check, build]` on the release job, drop rust-cache from it, pin
   actions to SHAs; add vitest + the Windows cross-check to CI (**M16**).
4. **M1–M4** — include `scrub_env` in the write round-trip; log/refuse malformed config
   instead of defaulting; make override-able config fields `Option`.
5. **H7/M8** — `--timeout` on `ctl run`; a Subscribe ack round-trip; fish-aware (or
   per-family) quoting.
6. **H5** — fix the Win32 error constants, the double-close path, and token entropy if
   Windows support is real; otherwise state "compiles-only, non-functional" in the README.
7. **M15** — drop `disable-library-validation`; sync README (entitlements, test counts,
   read-only command list) (**L30**).
