## Critical / High (new)

### H1. Concurrent `persist()` calls share one temp path and can tear `workspace.json` — `lib.rs:3653–3691, 5619–5650`
`DaemonServer::persist` is `&self` with no server-wide persist mutex, and every write
goes through the same fixed `workspace.json.tmp` path. Two interleaved persists
(open→open→write→rename) let the second writer's `write_all` land in the
already-renamed file via its stale fd, yielding `data_B` + leftover tail of `data_A`
when `len_B < len_A` — corrupt JSON; a crash in that window makes `load_workspace`
fall back to a fresh workspace (total state loss at next start). Reachable in normal
use: the accept loop's lazy flush (`lib.rs:4404–4413`) runs concurrently with handler
threads doing immediate persists (e.g. a divider drag's resize dirty-flag flushing
alongside the GUI's `UpdateWorkspaceLayout`). Same pattern in `WriteConfig` racing
`config.json.tmp` (`lib.rs:3167`). Fix: a persist mutex (or per-call unique temp
names).

### H2. v2 `BootstrapWorkspace` responses over 8 MiB are undeliverable — GUI attach bricks — `lib.rs:4778, 4852–4858, 2956, 818, 5577–5579`
Found independently by two agents. Every framed response goes through
`frame::encode`, which hard-rejects payloads over `MAX_FRAME_BYTES` (8 MiB) and drops
the connection with no response. Bootstrap attaches up to
`SCROLLBACK_REPLAY_LIMIT_BYTES` (2 MiB) *per pane* with no aggregate bound, and
`String::from_utf8_lossy` can expand an invalid-byte tail ~3×. Four panes with grown
scrollback (or two panes of binary spam) push the response past the cap; the GUI
always negotiates v2, so `bootstrap_workspace` fails with "daemon closed before
responding" on every attempt until scrollback files are manually deleted. The v1 path
has no encode cap, so the trap is v2-only. Fix: bound aggregate scrollback in the
response (or chunk it).

### H3. ResizeObserver goes stale on every re-render — divider drags never refit pre-existing panes — `ui/src/main.js:273–276, 290–301, 1279–1281`
`createTerminalView` observes the container exactly once, but every `render()` builds
fresh `.terminal` containers and `mountTerminalView` re-parents the xterm element
without re-targeting the observer, which keeps watching the detached node forever.
`resizeActiveSplit` deliberately skips refitting ("terminals refit via their
ResizeObserver"), so after any render (split, close, rename, pane-ended, zoom, swap,
reconcile), dragging a divider refits only panes created during the *last* render;
all others keep stale geometry and never send `resize_pane_terminal` — the daemon's
PTY columns stay wrong (output wraps at stale widths) until the next render or window
resize. Reproduced in a happy-dom harness: after one render the observer's only
target is detached. Invisible to the test suite because the ResizeObserver stub is a
no-op.

### H4. A failed liveness probe makes any mutating `ctl` command unlink a live-but-wedged daemon's socket — `lib.rs:2706–2744, 5243–5265`
`ensure_daemon` pings first; if the ping fails — exactly what a deadlocked daemon
does, now that `CLIENT_READ_TIMEOUT` (20s) bounds the wait — it calls
`remove_stale_socket`, which checks only that the path is a socket file, never
whether a process still holds the workspace flock. The wedged daemon keeps running
on the unlinked inode, unreachable by path; the replacement daemon can't take the
flock and exits after the 2.5s `DAEMON_LOCK_WAIT`; the client reports "daemon did not
become ready". Worse, `ctl shutdown` then prints "no daemon running" and exits 0
(`lib.rs:6116–6126`) while the orphaned daemon still holds the lock and the user's
shells. Recovery is manual `kill`. Fix: probe the flock (try-lock) before unlinking —
only remove the socket when the lock is acquirable.

### H5. Windows transport round 2: four more runtime defects (static analysis; Windows is the compiles-only tier) — `src-tauri/src/lib.rs`
- `ConnectNamedPipe` returning `ERROR_PIPE_CONNECTED` (535 — client connected between
  create and connect, a *success*) is not mapped, so a client connecting during
  daemon startup propagates an error that kills the daemon via the accept loop's
  catch-all (`lib.rs:634–651, 4483–4497`).
- Daemon-side pipe I/O passes a NULL `OVERLAPPED` on handles created with
  `FILE_FLAG_OVERLAPPED` (`lib.rs:394` vs `lib.rs:505–552`) — documented to
  fail/misbehave; the accepted connection can't reliably do I/O.
- `set_read_timeout`/`set_write_timeout` are silent no-ops (`lib.rs:486–495`),
  gutting `HANDSHAKE_READ_TIMEOUT`, `SUBSCRIBER_WRITE_TIMEOUT`, and
  `CLIENT_READ_TIMEOUT` on Windows — every anti-wedge bound is absent there.
- `try_clone` calls `DuplicateHandle` with `bInheritHandle = TRUE` (`lib.rs:456–474`),
  leaking IPC handles into spawned PTY shells (which run arbitrary commands).
The prior round (H5 in the 07-01 review) fixed the wrong error constants,
double-close, and token entropy; these four remained. Either fix and validate at
runtime, or state plainly in the README that Windows is compiles-only/non-functional.

## Medium (new)

### Frontend — settings modal data-loss and focus paths
- **M1. Settings repopulated from the secret-scrubbed `config-changed` summary; a later Save writes env values back as empty strings** — `ui/src/main.js:1403–1405`,
  `settings.js:67–73` vs `lib.rs:3566–3570, 1115–1135`. The broadcast summary nulls
  env values (`{"FOO": null}`); `envToText` renders `FOO=`; saving any other field
  then persists `{FOO: ""}` for every configured var. Reproduced end-to-end. Fix:
  re-fetch via `get_config` when repopulating, or skip the env field.
- **M2. Saving settings after a failed `get_config` replaces workspace config with defaults** — `main.js:1565–1586, 1645–1667`. Load failure is console-only; Save
  stays enabled and submits `{config: {}}`, which the daemon deserializes to
  all-defaults and atomically replaces `config.json` (only `scrub_env` survives, via
  the M1-round-trip guard). Block Save or show an error when the load failed.
- **M3. Background-event renders steal keyboard focus from the open settings modal** — `main.js:1233–1249, 1202–1218` via `events.js:64`. A `pane-ended`/reconcile
  render calls `terminal.focus()` while the modal is open; keystrokes intended for a
  settings field go into the PTY — including Enter. Reproduced. Guard
  `focusActiveTerminal` on `settingsModalOpen`.

### Daemon — resource caps are asymmetric (everything else is bounded; these aren't)
- **M4. No cap on pane count** — `PaneRegistry::create_pane` (`lib.rs:1530`) and the
  `CreatePane` handler (`lib.rs:2962–2977`) impose no limit; each pane costs a shell,
  a PTY, two threads, a vt100 model. One token-holding client exhausts PIDs/fds.
- **M5. Subscriber accumulation is uncapped and bypasses the connection cap** — `add_subscriber` (`lib.rs:1875–1931`) spawns two threads per subscriber with no
  bound; the connection slot is released at hand-off, so connect→Subscribe→hold
  loops accumulate subscribers until fd exhaustion, and `subscriber_count() > 0`
  permanently suppresses idle shutdown.
- **M6. Abandoned `wait` without `--timeout` pins a connection slot forever** — `handle_wait` (`lib.rs:3246–3326`) never observes client disconnect (the thread is
  inside the handler, not reading the socket); 256 of them wedge the daemon into
  refusing every new connection. Same family: no post-handshake read timeout on v2
  persistent connections — a partial frame pins a thread indefinitely
  (`lib.rs:4742` clears the timeout; `frame::read_bytes` blocks in `read_exact`).
- **M7. PTY spawn (openpty + fork/exec) runs under the global `TerminalStore` mutex** — `spawn_pane` (`lib.rs:2287–2328`), called with the store locked from bootstrap
  (N forks serialized), CreatePane, Ensure/Restart (`lib.rs:2948, 2977, 3043, 3048`).
  A slow spawn stalls all input/resize/liveness for every pane — the same wedge shape
  as the fixed H2, at fork+exec latency (5–50ms each). Move spawn out from under the
  lock.

### Availability / robustness
- **M8. Transient `accept()` errors kill the daemon and every shell** — `lib.rs:4483–4497`: only `WouldBlock` is non-fatal. macOS/BSD can return
  `ECONNABORTED` (a same-UID peer rapidly connecting and resetting — or just
  unlucky timing); `EMFILE`/`ENFILE` under fd pressure likewise. `thread::spawn`
  panicking on thread-creation failure unwinds the same loop. Make per-accept errors
  non-fatal (log + continue, with backoff on repeated `EMFILE`).
- **M9. Workspace identity is the raw, unnormalized path string** — `workspace_key` (`lib.rs:5721–5728`) hashes `path.display()` with no `canonicalize` (zero
  occurrences in the file). `--workspace /a/b` and `--workspace /a/b/` (or `..`,
  symlinks) are different workspaces: mutating commands silently spawn a second
  daemon for the same directory, read-only ones report "no daemon running", and
  `check_persisted_cwd` can't catch it. Canonicalize before hashing.
- **M10. `ctl run` shell-family detection can diverge from the daemon's actual shell** — `resolve_shell_family` (`lib.rs:7309–7318`) falls back to `default_shell()`
  in the *ctl* process's environment when config doesn't pin `shell`, while the pane
  used the *daemon*'s environment. Divergence (GUI-launched daemon vs fish terminal)
  emits the wrong status idiom, the marker never prints, and `run` hangs without
  `--timeout`. Have the daemon report its resolved shell in the status summary.

### Scrollback / persistence efficiency
- **M11. Scrollback write path pays open+write+close+stat per ≤8 KiB chunk** — `append_scrollback` + `cap_scrollback_file` (`lib.rs:2155–2171, 5665–5671`); four
  syscalls per reader chunk on the hottest path, plus `broadcast` serializes
  `PtyOutput` JSON even with zero subscribers (`lib.rs:2114`). Cache an append handle
  and an in-memory byte counter; skip serialization when the subscriber list is
  empty.

### Distribution
- **M12. The updater is wired end-to-end but functionally dead** — the plugin is
  registered (`lib.rs:8128`) but nothing ever calls `check()` (no Rust or frontend
  usage; `@tauri-apps/plugin-updater` in package.json is unused), and
  `updates.sgian.dev` does not resolve in DNS (README: "real hosting is deferred").
  CI signs and uploads updater artifacts every release, but no shipped build can
  discover an update. Either land a check + UI affordance and provision the feed
  before release, or mark the machinery aspirational in the release checklist.
  (Carries forward prior L27.)
- **M13. `dtolnay/rust-toolchain@stable` is a mutable ref in all three CI jobs, including the secret-bearing release job** — `ci.yml:24, 60, 115`, contradicting the
  workflow's own "all actions pinned to SHAs" header (prior H6, partially fixed:
  `needs:` and cache-free release job are done). Pin `@stable`'s current commit SHA
  per the in-file TODO.
- **M14. No tag↔version consistency check in the release job** — tagging `v0.2.0`
  without bumping `tauri.conf.json` ships artifacts whose embedded version is stale;
  updater semver comparison then sees no upgrade. Two-line step comparing
  `GITHUB_REF_NAME` to the config version closes it.

## Structural observation

The 07-01 review found coverage inverted toward pure modules; that is now largely
fixed for the frontend (`main.test.js` boots the real orchestrator against a stubbed
`__TAURI__`) and the new defect cluster has moved accordingly: **cross-thread and
cross-process race windows** (persist temp-path race, socket-unlink race, observer
lifecycle across re-renders) and **resource-cap asymmetries** (panes, subscribers,
abandoned waits, stalled frames are unbounded while queues, scrollback, titles,
grids, and connections are all carefully bounded). The remaining test gaps — mount
lifecycle, drag resize, settings-modal error paths, connection/subscriber caps — sit
exactly on top of this review's Highs and Mediums.

   `WriteConfig`).

   before unlinking a "stale" socket. Both are availability traps with painful manual
   recovery.
3. **H3 + M1–M3** — re-observe on mount; repopulate settings from `get_config`;

   re-arm a read timeout between v2 frames; move spawn out from under the store mutex.
5. **M8–M10** — non-fatal per-accept errors; canonicalize workspace paths; daemon-reported
   shell family.
6. **M12–M14** — decide the updater story before release (provision the feed + a check
   call, or strip the machinery); pin the toolchain SHA; add the tag↔version step.
7. **H5** — fix the four Windows transport defects or declare the platform
   compiles-only in the README; **M17** — one-time legacy-key migration.
