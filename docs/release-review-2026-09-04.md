# Public release review — 2026-09-04

Reviewed baseline: `964dee7`, plus the working-tree fixes described here.
The review focused on daemon trust boundaries, process/configuration handling,
UI content and native bridges, dependencies, and release automation.
Status: **release candidate prepared; platform and production-signing gates
must pass before public distribution.** No tag, push, release publication, or
repository-visibility change was performed during this review.

## Fixed findings

| Priority | Finding and consequence | Fix and evidence |
| --- | --- | --- |
| P1 | Windows WebView2 accepted shell-input messages from any document and did not restrict navigation. Navigating the terminal view to an attacker-controlled page could expose the bridge. | Exact document checks on incoming messages and outgoing output; blocked foreign/frame navigation, popups, permissions and downloads; restrictive CSP. Protocol checks reject hostile URLs. WinUI runtime verification remains a Windows CI gate. |
| P2 | `ctl process` inherited variables listed in `scrub_env` and ignored configured `env`, diverging from shell/agent execution. | Applies the current environment policy before spawn. Rust integration test checks removed variables, explicit values and override precedence using a real child. |
| P2 | Invalid startup configuration was treated as an absent layer, potentially discarding a scrub list or inheriting a more permissive agent mode. File reads also skipped semantic validation. | Refuse startup before creating runtime state; validate disk configuration; preserve the last valid configuration during failed reloads. Regression tests cover malformed JSON and invalid permission/restore modes. |
| P2 | Native Windows IPC and discovery could buffer a line without limit; subscription setup could wait indefinitely, and cancelled discovery could leave a helper running. | Bounded streaming line reader, handshake/ack deadlines, current-user pipe ownership check, and helper termination on cancellation/failure. C# tests cover line bounds, EOF, cancellation and buffered messages. |
| P2 | Native macOS terminal links used SwiftTerm's arbitrary scheme opener. Terminal output could disguise a local-file or custom-handler link. | Only HTTP(S) URLs without credentials are opened; regression tests reject local files and custom schemes. |
| P2 | Native macOS socket cancellation could close/reuse a descriptor after lookup but before a syscall. | Duplicate the socket under the descriptor lock for each operation, close the duplicate afterward, and mark descriptors close-on-exec. Native client compilation and live daemon round-trip passed. |
| P1 | Release platform jobs published independently; a signing or upload failure could leave a public partial release. Windows expected a v1 ZIP although configuration generates v2 EXE/signature artifacts. | Stage all signed artifacts, use the EXE signature, verify every updater artifact against the embedded key, generate one complete feed/checksum set, upload to a draft, then publish. actionlint and release-assembly regressions pass; real minisign validation accepts signed data and rejects tampering. |
| P2 | Update discovery depended on a separately provisioned domain with no feed deployment in this repository. | Use `https://github.com/craigcode/sgian/releases/latest/download/latest.json`, generated by the release workflow. The repository and release assets must be public for anonymous downloads. |
| P2 | Cache-backed validation jobs received updater signing secrets; dependency audits were not release gates. | Validation builds are unsigned and receive no signing secrets. Add npm, RustSec, and transitive NuGet audit gates, pin Rust 1.94.0 and use Node 22. |
| P2 | npm audit reported vulnerable Nano ID and PostCSS build dependencies; vendored xterm was absent from the dependency manifest. | Update compatible lockfile entries. Pin official xterm packages and compare all vendored JS/CSS bytes before building. All four assets exactly matched upstream; terminal code was unchanged. |
| P3 | Unix soak script wrote to the first unrelated daemon log it found and used unsupported macOS thread-count syntax while still reporting success. | Remove unrelated log writes and unreliable thread sampling; clean up the specific test daemon on exit. The soak checks concurrent commands and session operations, not leak freedom. |

## Remaining release gates and risks

1. **Run the changed CI workflow on the final commit.** Linux bundle/runtime
   checks and Windows WinUI/installer/pipe checks cannot be substituted by the
   successful macOS runs. The workflow's release jobs depend on these checks.
2. **Production signing and update exercise.** Configure the Developer ID,
   notarization, and updater secrets named in `.github/workflows/ci.yml`.
   The final signature verifier rejects a private/public key mismatch. Exercise
   installation and a real version-to-version update from production-signed
   artifacts before treating updates as operational. The local `.app` is an
   unsigned validation artifact and must not be presented as notarized.
3. **Platform packaging scope.** The public release workflow publishes Tauri
   builds for the runner architectures. It does not yet release both Intel and
   Apple Silicon macOS builds. Native SwiftUI/WinUI bundles remain CI artifacts;
   macOS native Developer ID signing/notarization is not wired. Windows NSIS/MSIX
   lacks Authenticode signing and may trigger SmartScreen warnings.
4. **Linux upstream debt.** `glib` 0.18.5 carries
   [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html):
   unsound `VariantStrIter` operations, fixed upstream in 0.20.0. Tauri's GTK3
   dependency chain requires the older series, so a direct version bump is not
   compatible. No direct use of that iterator was found in Sgian's source; its
   complete transitive reachability was not proven. Seventeen maintenance
   notices cover GTK3 bindings, proc-macro-error, portable-pty's serial crate,
   and rust-unic crates. Retain visibility of these warnings and evaluate an
   upstream migration or a reviewed backport; do not claim they are fixed.
5. **Repository launch settings.** Make the repository and releases publicly
   readable only after reviewing history and repository content. Enable private
   vulnerability reporting, protect the default branch and release tags, and
   restrict who can trigger secret-bearing tag builds. These hosted settings
   were not changed by this review.
